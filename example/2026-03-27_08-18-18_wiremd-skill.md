## Complete DSL Component Inventory

### 1. Headings

Standard markdown headings. Support attribute syntax.

```
# Page Title
## Section {.grid-3}
### Card Title
```

```wiremd
# Page Title
## Section
### Card Title
```

Grid trigger: `{.grid-N}` on a heading collects subsequent subheadings as grid items.

### 2. Buttons

```
[Button Text]                    → default button
[Button Text]*                   → primary button (asterisk suffix)
[Button Text]{.primary}          → primary via class
[Button Text]{.secondary}        → secondary variant
[Button Text]{.danger}           → danger variant
[Cancel]  [Submit]*              → button group (multiple on one line)
[:icon-name: Label]              → button with icon
```

```wiremd
[Default]

[Primary]*

[Secondary]{.secondary}

[Danger]{.danger}

[Cancel]  [Submit]*
```

Variants: `primary`, `secondary`, `danger`
Button type props: `{type:submit}`, `{type:reset}`

### 3. Text Inputs

```
[____________________________]           → text input (underscores = width)
[****************************]           → password input (asterisks)
[Placeholder text___________]            → input with placeholder (text before underscores)
[____________________________]{required} → required input
[____________________________]{type:email}     → email input
[____________________________]{type:tel}       → telephone input
[____________________________]{type:url}       → URL input
[____________________________]{type:number}    → number input
[____________________________]{type:date}      → date input
[____________________________]{type:search}    → search input
[____________________________]{disabled}       → disabled input
```

```wiremd
## Text Inputs

[____________________________]

[****************************]

[Placeholder_______________]

[____________________________]{type:email}

[____________________________]{disabled}
```

Input types from types.d.ts: text, email, password, tel, url, number, date, time, datetime-local, search
Props: required, disabled, placeholder, pattern, min, max, step, width

### 4. Textareas

```
[____________________________]{rows:5}         → textarea with 5 rows
[Placeholder text]{rows:3}                     → textarea with placeholder
```

```wiremd

```

Trigger: `{rows:N}` attribute on a bracket expression.

### 5. Select / Dropdown

```
[Choose an option v]         → dropdown (trailing 'v' = dropdown indicator)
- Option 1                   → options as list items following the dropdown
- Option 2
- Option 3
```

```wiremd
[Choose a relay v]
- wss://relay.damus.io
- wss://nos.lol
- wss://purplepag.es
```

The `v` suffix inside brackets signals a select element. Options come from the immediately following markdown list.

### 7. Radio Buttons

```
(*) Selected option  ( ) Unselected option
(•) Also selected    ( ) Another option
(x) Selected too     ( ) Unselected
```

```wiremd
(*) Daily  ( ) Weekly  ( ) Monthly
```

Requires 2+ radio patterns on same line. Markers: `*`, `•`, `x` = selected; space = unselected.

### 8. Container Directives (:::)

```
::: containerType {attributes}
content here
:::
```

```wiremd
::: hero
## meta.nostr.io
Sign in with your Nostr identity to manage the metadata mirror.

[Login with NIP-07]{.primary}
:::
```

Valid container types:
- **hero** — Hero/banner section
- **card** — Card component
- **modal** — Modal dialog
- **sidebar** — Sidebar panel
- **footer** — Footer section
- **alert** — Alert/notification box
- **grid** — Grid layout (use `{columns=N}`)
- **layout** — Generic layout wrapper
- **section** — Generic section
- **form-group** — Form field group
- **button-group** — Button row

**Nesting limitation**: Container nesting (`:::grid` wrapping `:::card`) does NOT work — the inner `:::` closers prematurely terminate the outer container. The `:::` syntax is **single-level only**. For grid layouts with card-like items, use the heading-based `{.grid-N}` syntax (see section 11).

### 9. Navbar / Navigation

```
::: navbar
```

Navbar is a container type. Navigation items are rendered as buttons inside the navbar container.

### 11. Grid Layout (Heading-based)

```
## Features {.grid-3}

### :rocket: Fast
Lightning quick performance

### :shield: Secure
Bank-level security

### :gear: Flexible
Fully customizable
```

```wiremd
## Features {.grid-3}

### :rocket: Fast
Lightning quick performance

### :shield: Secure
Bank-level security

### :gear: Flexible
Fully customizable
```

The `{.grid-N}` class on a heading triggers grid collection. Each subheading (one level deeper) becomes a grid item. Content between subheadings is collected into each item.

**This is the only working grid mechanism.** The AST types define a `:::grid {columns=N}` container syntax, but container nesting is non-functional (inner `:::` closers terminate the outer container). The heading-based grid produces card-like styling automatically and supports 2, 3, 4+ columns.

### 20. Attribute Syntax

Curly-brace suffix on elements:
```
{.className}           → adds CSS class
{.primary}             → semantic class (buttons use as variant)
{.secondary}           → secondary variant
{.danger}              → danger variant
{:disabled}            → state modifier
{required}             → boolean attribute
{type:email}           → key:value attribute
{rows:5}               → key:value (textarea rows)
{columns=N}            → container attribute (grid columns)
{action:/submit}       → form action
{method:post}          → form method
```

State modifiers (via colon prefix): disabled, loading, active, error, success, warning.

### 29. Unimplemented AST Types (v0.1.5)

The following types exist in `types.d.ts` but have **no parser support** — they cannot be rendered:

- **tabs** / **tab** — Tabbed interface
- **accordion** / **accordion-item** — Collapsible sections
- **breadcrumbs** / **breadcrumb-item** — Breadcrumb navigation
- **badge** — Inline badge
- **loading-state** — Loading indicator
- **empty-state** — Empty state placeholder
- **error-state** — Error state placeholder

## Known Issues & Workarounds (v0.1.5)

1. **CSS Scoping**: wiremd's sketch style includes bare `* { }` selectors. Must wrap in `.wiremd-rendered { }` using CSS nesting.
2. **Parser crash**: Input + button on same line (`[___] text [Button]`) crashes parser. Split across lines.
3. **Container nesting**: Multi-level nesting works but must ensure `:::` delimiters are properly paired.
4. **Error resilience**: Wrap rendering in try/catch — one parse failure halts all subsequent blocks in a forEach.

## Skill Architecture Decision

**Structure**: SKILL.md (orientation + syntax overview) + references/syntax-reference.md (complete element catalog with examples)

This follows progressive disclosure: SKILL.md provides the pattern vocabulary and when-to-use guidance; the reference file provides copy-paste examples for each component.
